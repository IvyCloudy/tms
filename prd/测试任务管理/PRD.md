## 1. 需求概述

### 1.1 需求背景

随着业务版本迭代加速，测试团队面临多任务并行、跨角色协同、信息分散等问题：

- **任务散落**：案例、执行记录、缺陷、评审分散在 Excel、禅道、飞书文档等多个系统中，无法形成闭环视图。
- **切换成本高**：测试工程师通常同时参与 3~5 个并行任务，系统缺少统一的"任务上下文"入口，每次切换都需要多次跳转。
- **进度不透明**：管理者难以快速掌握各任务的设计 / 执行 / 评审进度，无法及时识别风险。
- **协作低效**：评审、审批、缺陷指派等流程依赖线下沟通，缺少统一待办入口。
- **报告手工化**：测试报告多由测试负责人手动撰写 Word/PPT，指标口径不统一，归档与追溯困难。

本次需求构建统一的测试任务管理平台（TMS），将测试生命周期内的所有工作聚合到"一个任务 + 一个上下文"下，提升测试团队的协同效率与过程透明度。

### 1.2 目标与价值

**核心思路**：以"测试任务"为核心对象，以"测试子任务 / 测试阶段 / 测试轮次"为全局测试范围上下文，一站式串联设计、执行、缺陷、报告、评审五大环节；左上角全局任务切换器 + 顶部全局范围切换，在任意菜单页都能随时保持 / 切换当前上下文。

| 价值点 | 说明 |
|---|---|
| 一个上下文，全页贯通 | 左上任务切换器 + 顶部"测试子任务 / 阶段 / 轮次"下拉；切换一次，设计 / 执行 / 缺陷 / 报告 / 评审五个菜单同步生效。 |
| 一个工作台，三秒进入状态 | 首页卡片化展示"我的任务 + 我的待办 + 团队动态 + 公告"，登录即看到进度、待办与紧急项；统计卡与下方面板双向联动。 |
| 全链路闭环 | 设计 → 执行 → 缺陷 → 报告 → 评审 模块数据打通；执行失败一键提 Bug，缺陷可回链案例，报告一键发起评审，评审结果回写任务状态。 |
| 过程可度量 | 任务进度、案例覆盖、缺陷分布、通过率、评审通过率等关键指标实时可视，帮助管理者及时识别风险。 |

### 1.3 功能范围与菜单结构

平台采用"顶栏 + 左侧菜单 + 主内容区"三段式经典布局，共 **7 个一级菜单**。顶栏左上角是全局任务切换器（与菜单同宽），右侧放置"测试子任务 / 测试阶段 / 测试轮次"等测试范围下拉；不再放置消息、搜索、帮助、用户等无关入口。

```
TMS 测试任务管理平台
├── [顶栏左侧] 任务切换器（宽 200px，与菜单同宽；tooltip 显示完整任务名）
├── [顶栏中部] 页面标题（工作台 / 测试任务 / 设计管理 / 执行管理 / 缺陷管理 / 测试报告 / 评审管理）
├── [顶栏右侧] 全局测试范围切换（测试子任务 · 测试阶段 · 测试轮次）
│
├── ◈ 工作台           // 默认首页：卡片聚合任务 + 待办
├── ◎ 测试任务         // 任务列表（表格 + 统计 + 搜索）
├── ◇ 设计管理         // 案例管理（表格）+ 测试大纲（XMind）
├── ▷ 执行管理         // 执行概览 + 案例执行列表
├── ◆ 缺陷管理         // 缺陷概览 + 缺陷列表（表格 + 搜索）
├── ◫ 测试报告         // 阶段 / 子任务 / 任务总报告 + 指标可视化 + 签署归档
└── ◐ 评审管理         // 评审概览 + 评审列表（表格 + 搜索）
```

| 菜单 | 核心定位 | 主要页面 / 区块 |
|---|---|---|
| 工作台 | 个人聚合首页（跨任务） | 数据总览、我的测试任务、快捷入口、我的待办、团队动态、公告 |
| 测试任务 | 任务生命周期管理 | 状态统计条、筛选区、任务表格（任务编号 / 名称 / 状态 / ST 双列 / UAT 双列 / 截止日期 / 操作） |
| 设计管理 | 案例设计与复用 | 子任务+阶段联动、案例管理（表格 + 搜索）、测试大纲（XMind） |
| 执行管理 | 测试执行过程管理 | 子任务+阶段+轮次联动、执行概览卡片、进度条、案例执行列表 |
| 缺陷管理 | 缺陷全生命周期 | 子任务+阶段联动、缺陷概览、缺陷列表（表格 + 搜索） |
| 测试报告 | 测试结果交付与归档 | 报告头信息、核心 KPI、用例分布环形图、缺陷多维度分布、阶段通过率、团队负荷、风险遗留、结论与签署 |
| 评审管理 | 评审与审批 | 子任务联动、评审概览、评审列表（类型 / 方式 / 状态 / 结果） |

### 1.4 角色与权限

| 角色 | 主要使用场景 | 关键权限 |
|---|---|---|
| 测试工程师 | 案例设计、执行、缺陷提报 | 参与任务的设计 / 执行 / 评审 / 提 Bug |
| ST 负责人 / UAT 负责人 | 承担系统测试 / 用户验收两个阶段的执行 | 任务 ST / UAT 负责人在任务列表单独列出，状态独立流转 |
| 测试负责人 | 任务创建、进度跟踪、发起评审、生成报告 | 创建任务、指派人员、归档、发起 / 主持评审、生成并签署测试报告 |
| 开发工程师 | 处理缺陷 | 查看被指派的缺陷、修复与回归确认；在报告签署区进行开发负责人签署 |
| 产品经理 | 需求与报告确认 | 参与评审、在报告签署区进行产品负责人签署 |
| 测试经理 | 宏观进度与风险把控 | 所有任务只读 + 统计报表 + 审批 + 归档报告 |

## 2. 需求内容

### 2.1 全局框架与上下文

平台的所有业务页面共用统一的顶栏与左侧菜单。顶栏承担两类核心上下文入口：**当前测试任务** 与 **当前测试范围**（子任务 / 阶段 / 轮次）。

#### 2.1.1 顶栏区域结构

| 区域 | 尺寸 | 说明 |
|---|---|---|
| 左侧：任务切换器 | 宽 200px · 高 52px | 与左侧菜单同宽；显示当前任务名称（不再显示 LOGO 与产品名），鼠标悬浮在右侧浮出 tooltip（浅色背景 + 深色字）完整展示任务名。点击展开下拉面板：搜索框 + 最近访问 + 我参与的 + 新建任务。 |
| 中部：页面标题 | — | 显示当前菜单名（工作台 / 测试任务 / 设计管理 / 执行管理 / 缺陷管理 / 测试报告 / 评审管理），左侧细竖分隔线。不再展示"工作台 / XXX"面包屑。 |
| 右侧：测试范围下拉 | 自适应 | 视菜单不同而显示不同字段：设计 / 缺陷 显示"测试子任务 + 测试阶段"；执行 额外显示"测试轮次"；报告 显示"测试子任务 + 测试阶段（仅阶段报告模式启用）"；评审 仅显示"测试子任务"。字段前加红色星标表示必选。 |
| 右上角 | — | **不显示**消息、搜索、帮助、用户等图标，保持顶栏专注于上下文。 |

#### 2.1.2 左侧菜单

- 宽 200px，深色背景（`#1e2736`），**7 个菜单项**：工作台 / 测试任务 / 设计管理 / 执行管理 / 缺陷管理 / **测试报告** / 评审管理。
- **菜单项不显示待办数角标**，也不显示"导航菜单"等分组标题，保持极简。
- 菜单激活态：背景加深 + 左侧 3px 蓝色竖条（`#0052d9`）。
- 图标采用 Unicode 几何符号（`◈ ◎ ◇ ▷ ◆ ◫ ◐`），保证跨平台一致性。

#### 2.1.3 全局任务切换（TMSGlobal）

- 全局对外 API：`TMSGlobal.mount / getCurrentId / setCurrent / upsertTask / onChange`。
- 任务池以 `localStorage` 保存，支持跨 Tab 同步；切换任务后所有已挂载页面通过 `onChange` 统一刷新。
- 切换成功后在页面顶部弹出 Toast："已切换到 XXX"（1.8s 自动消失）。
- 工作台任务卡片点击可触发 `setCurrent`；任务列表"任务编号"列点击也可触发切换，当前任务行左侧有蓝色竖条 + "● 当前"徽标。
- 下拉面板分组：**最近访问**（按最近切换时间倒序 TOP5）/ **我参与的**（全部）/ **搜索结果**（输入关键字时显示）/ **＋ 新建任务**（始终置底）。

#### 2.1.4 全局测试范围切换（TMSScope）

- 范围维度：**测试子任务 · 测试阶段（冒烟 / 系统测试 ST / 回归 / 用户验收 UAT）· 测试轮次**。
- 全局通过 `localStorage` 以**可见名称**持久化，跨页 / 跨 Tab 共享：设计管理切换"支付核心 API 重构 + 系统测试（ST）"后，切到执行 / 缺陷 / 报告管理会自动选中相同的子任务与阶段。
- 各页面下拉通过 `TMSScope.pickMatch` 按名称进行匹配（忽略大小写 / 空格），匹配不到时回落到该页默认值并回写全局。
- **切换主任务时**：子任务 / 阶段 / 轮次自动清空，由各页按其任务的默认子任务重建下拉。
- **评审管理**选择"全部子任务"时不回写全局，避免覆盖其他页面的精确选择。

> **设计要点**：任务切换器是"主上下文中枢"，测试子任务 / 阶段 / 轮次是"细粒度上下文"。两者分别解决"换任务"与"换测试范围"的问题，在任意菜单页都保持联动。**工作台除外**（展示跨任务的个人聚合视图）。

### 2.2 工作台

工作台是登录后的默认落地页，定位为"个人聚合视图"，**跨任务展示**当前用户关联的所有信息。顶部只显示副标题"欢迎回来，XXX · 今天是 YYYY 年 M 月 D 日 周 X"，**不显示"工作台"标题**（标题已落到顶栏）。

#### 2.2.1 页面结构

```
工作台
├─ 副标题（欢迎语 + 日期）
├─ 数据总览（4 张统计卡）                      ← 可点击联动下方面板
├─ 左右主栏（grid: 1fr 380px）
│   ├─ 左列
│   │   ├─ 我的测试任务（2 行 × 3 列 + 更多按钮，每次加载 3 个）
│   │   ├─ 快捷入口（6 个精简入口）
│   │   └─ 团队动态（时间线）
│   └─ 右列
│       ├─ 我的待办（全部 / 逾期 / 今日 Tab + 批量操作）
│       └─ 公告 & 消息
```

#### 2.2.2 数据总览（4 张可点击统计卡）

| 卡片 | 指标口径 | 点击联动 | 配色 |
|---|---|---|---|
| 进行中任务 | 当前用户参与，状态 ∈ {设计中 / 执行中 / 评审中} 的任务数 | 滚动并高亮"我的测试任务"面板，自动切换到"执行中" Tab | 蓝（sc-blue） |
| 待办事项 | "我的待办"全部未完成项总数 | 滚动并高亮"我的待办"面板，切到"全部" Tab | 橙（sc-orange） |
| 待处理缺陷 | 指派给我且状态 ∈ {待处理 / 重开} 的缺陷数 | 跳转缺陷管理，预置"处理人=我 + 状态=待处理/重开" | 红（sc-red） |
| 本月已完成 | 当前用户本月完成执行的案例数 + 关闭的缺陷数 | 跳转工作台团队动态，按"我的 + 本月"筛选 | 绿（sc-green） |

**卡片规格**：
- 尺寸：`flex:1`，等宽 4 列；`padding:14px 18px`；背景 `#fff`；边框 `#e5e9ef`；圆角 6px。
- 主数值：26px · 600 字重；悬浮变 `#0052d9`。
- 副文案：11.5px · 灰色，格式"较上周 ↑12%"或"其中致命+严重 5"。
- 右上角 34×34 软色图标方块，随卡片色系配色。
- 悬浮：左侧浮出 3px 竖条（与卡片色系一致），边框变蓝，阴影 `0 2px 8px rgba(0,82,217,.08)`。
- 点击：下方对应面板闪烁一次高亮边框（`panelFlash` 1.2s 动画）。

#### 2.2.3 我的测试任务（2 行 × 3 列网格 + 更多）

**布局规则**：
- 网格：4 列固定，默认显示 **2 行最多 8 张卡**；
- 超过 8 条时，在面板右下角显示「**更多 (剩余 N)**」按钮；点击一次展开下一批 8 条（4×2），**无上限**，逐批懒加载；
- 若无数据，显示空态："暂无任务，点击左上角切换或 + 新建"。

**Tab 筛选**：全部 / 设计中 / 执行中 / 评审中 / 已完成；每个 Tab 旁显示数量角标。

**卡片字段（仅 2 项）**：

| 字段 | 展示样式 | 说明 |
|---|---|---|
| 任务名称 | 13.5px 600 字重，**单行省略+Tooltip** | 点击卡片：切换为当前任务（`TMSGlobal.setCurrent`），所有菜单页上下文同步；当前任务卡左侧 3px 蓝条 + 右上角"● 当前任务"徽标。 |
| 子任务总数 | 12px 灰色副文案 | 格式"共 N 个子任务"，读取当前任务的子任务配置计数。 |

> 卡片不展示进度条、ST/UAT 状态徽标等详细信息，保持极简；详细信息在"测试任务"菜单展开。

#### 2.2.4 快捷入口（6 项）

按"高频创建 + 核心流转"双轴精简：

| 图标 | 名称 | 目标 | 用途 |
|---|---|---|---|
| `+` | 新建任务 | proto-task-list.html（并打开新建弹窗） | 高频创建 |
| `✎` | 设计案例 | proto-design.html | 高频创建 |
| `▷` | 执行测试 | proto-execution.html | 核心流转 |
| `◐` | 发起评审 | proto-review.html（并打开发起弹窗） | 核心流转 |
| `◆` | 缺陷管理 | proto-defect.html | 核心流转 |
| `▤` | 测试报告 | proto-report.html | 核心流转 |

- 3×2 网格；每项 `padding:14px 8px`；悬浮背景变 `#f0f6ff`、图标反白 `#0052d9 → #fff`。
- 所有入口默认携带当前任务上下文；未选择任务时入口跳转后提示"请先选择测试任务"。

#### 2.2.5 我的待办（分类 Tab + 批量操作）

**Tab**：全部 / 逾期 / 今日；每 Tab 带计数 `tab-num`。

**待办类型（按 icon 底色区分）**：

| 类型 | 图标底色 | 来源 | 处理跳转 |
|---|---|---|---|
| 缺陷 `bug` | 红 `#fef0f0` | 指派给我且状态 ∈ {待处理,重开} | 缺陷管理详情页 |
| 评审 `review` | 紫 `#f3e8ff` | 作为参与人且评审状态 ∈ {待评审,评审中} | 评审管理详情页 |
| 审批 `approve` | 橙 `#fff3e0` | 任务变更 / 案例评审等待审批 | 审批弹层 |
| 执行 `exec` | 蓝 `#e8f3ff` | 案例执行状态=待执行且执行人=我 | 执行管理对应轮次 |

**列表项字段（一行）**：
1. 左侧复选框（用于批量操作）
2. 类型图标（28×28，圆角 4px）
3. 标题（单行省略；高优先级左侧 3px 红条）
4. 副信息：`来源任务名 · 子任务 · 截止时间`
5. 右侧：`处理 / 评审 / 审批 / 执行` 按钮（根据类型动态）

**优先级色带（左 3px 竖条）**：`priority-high` 红 / `priority-mid` 橙 / `priority-low` 灰。

**默认条数 + 更多**：默认显示 10 条；超过 10 条时底部显示「更多 (剩余 N)」，点击每次追加 10 条。

**排序**：已逾期 > 今日到期 > 本周到期 > 其他；同级按创建时间倒序。

**批量操作（已取消按需恢复）**：当前版本**不启用**批量操作栏；单项"处理"按钮直达详情页并自动携带任务上下文。

**跳转携带上下文规则**：
- 点击待办项 → 读取来源任务 ID → `TMSGlobal.setCurrent(taskId)` → 跳对应菜单页 → 读取来源子任务/阶段/轮次 → `TMSScope.set()` → 定位到具体记录。
- 若来源任务已归档 / 不存在，Toast 提示："任务已归档或不可访问"，不跳转。

#### 2.2.6 团队动态

- 时间线样式；每项包含：头像、姓名、动作、对象、时间。
- 动作类型：提交案例 / 关闭缺陷 / 完成执行 / 创建任务 / 发起评审 / 归档报告。
- 默认显示 10 条，"查看全部" 跳转独立页（二期）。

#### 2.2.7 公告 & 消息

- 每条含 tag：`置顶`（红）/ `系统`（蓝）/ `规范`（绿）。

#### 2.3.2 任务与环境状态字典

| 维度 | 取值 | 色值 |

#### 2.3.3 任务状态流转

```
草稿 → 设计中 → 执行中 → 评审中 → 已完成 →（30 天后可归档）
```

- **草稿**：新建后未启动，可随意编辑，不计入统计。
- **设计中**：启动后进入案例设计阶段（设计管理菜单）。
- **执行中**：案例评审通过，进入执行阶段（ST、UAT 状态独立流转）。
- **评审中**：执行完毕，提交测试总结评审。
- **已完成**：总结评审通过后自动转为已完成。
- **已归档**：30 天后可归档，归档后默认不在列表显示，需勾选"包含已归档"才出现。

### 2.4 设计管理

### 2.6 缺陷管理

缺陷全生命周期管理。主视图为"表格"，在顶栏范围筛选（子任务 + 阶段）下支持搜索、多条件筛选、分页。

#### 2.6.1 顶栏范围筛选

- 测试子任务、测试阶段：与设计 / 执行管理共享选中值。
- 右上角操作：导出缺陷单 / + 提交缺陷。

#### 2.6.2 缺陷概览（6 张卡片）

| 卡片 | 统计口径 | 附加文案 |
|---|---|---|

| 区域 | 内容 |
|---|---|

| 操作列 | 查看 / 分配 / 关闭 |

#### 2.6.4 状态与分级字典

| 维度 | 取值 |
|---|---|
| 状态 | 待处理 / 修复中 / 已修复 / 验证中 / 已关闭 / 重开 / 已拒绝 |
| 严重程度 | 致命 Blocker / 严重 Critical / 主要 Major / 次要 Minor / 轻微 Trivial |

| 类型 | 功能 / UI / 性能 / 安全 / 兼容性 / 其他 |

#### 2.6.5 状态流转

```
待处理 → 修复中 → 已修复 → 验证中 → 已关闭

                           重开 → 修复中
待处理 → 已拒绝（无效单；可申诉回到待处理）
```

- 验证不通过 → 重开 → 回到修复中。
- 无效单 → 已拒绝；被拒绝后可申诉转回待处理。
- 关闭后 30 天自动归档；归档单仅可只读查看。

**校验**：标题 5–80 字；重现步骤 ≥ 20 字；至少 1 个关联案例 **或** 1 张截图。

### 2.7 测试报告

测试报告菜单定位为"**结果交付与归档**"，面向测试负责人、产品/开发 Leader、QA 总监，支持 3 种级别的报告：**阶段报告 / 子任务报告 / 任务总报告**。

#### 2.7.1 顶栏范围筛选

| 字段 | 是否必选 | 说明 |
|---|---|---|
| 测试子任务 | 必选 | 与设计 / 执行 / 缺陷共享值 |
| 测试阶段 | **阶段报告**模式必选；子任务报告 / 任务总报告模式禁用 | 下拉禁用时置灰，仍显示但不可交互 |

#### 2.7.2 报告元信息（头部卡）

| 字段 | 示例 | 说明 |
|---|---|---|
| 报告标题 | "支付业务 2026Q2 迭代测试 · 系统测试（ST）阶段报告" | 根据报告类型自动生成，可手动编辑 |
| 报告类型标签 | `阶段报告` / `子任务报告` / `任务总报告` | 3 色徽标（橙/蓝/绿） |
| 结论徽章 | `通过 / 有条件通过 / 未通过 / 草稿` | 4 色圆点徽章 |
| 报告编号 | R-2026-ST-0142 | 规则：`R-{年}-{类型码}-{序号4位}`；类型码：SMOKE / ST / UAT / REG / SUB / TASK |
| 测试任务 | T001 支付业务 2026Q2 迭代测试 | 自动取当前任务 |
| 测试子任务 | 支付主流程 | 自动取范围筛选值 |
| 测试阶段 | 系统测试 ST / 全部 | 阶段报告时显示具体阶段，其他模式显示"全部" |
| 测试周期 | 2026-03-21 ~ 2026-04-25（共 36 天） | 自动取所选阶段 / 子任务的实际执行周期 |
| 报告生成时间 | 2026-04-25 18:02 | 最后一次重新生成时间 |
| 负责人 | 李测试 | 当前任务测试负责人 |

**右侧操作区**：
- 报告类型切换（Segmented）：`阶段报告 / 子任务报告 / 任务总报告`；
- `⟲ 历史报告`：弹出模态列出该任务的所有历史报告（编号/名称/类型/状态/负责人/生成时间/查看）；
- `🖶 打印`：调用 `window.print`，应用打印样式；
- `⤓ 导出`：导出 PDF / Word 两种格式；
- `发起评审`（主按钮）：生成评审编号，自动创建"测试总结评审"，参与人默认为开发/产品/测试负责人。

#### 2.7.3 核心 KPI（4 卡）

| KPI | 口径 | 对比基线 |
|---|---|---|
| 执行完成率 | 已执行 / 计划总数 × 100% | vs 上一阶段 |
| 用例通过率 | 通过 / (通过+失败+阻塞) × 100% | vs 上一阶段 |
| 缺陷总数 | 当前范围全部缺陷数；副文案"未关闭 X · 致命+严重 Y" | 较上阶段 ±N |
| 缺陷密度 | 缺陷总数 / 代码规模（KLOC） | 基线 ≤ 1.5 |

**样式要求**：
- 4 卡等宽；主数值 26px · 700 字重；
- 执行完成率蓝色、通过率绿色、缺陷总数橙色、缺陷密度红色；
- 右上角趋势徽标：`↑ +8.2% vs 上一阶段`（升跌颜色区分）。

#### 2.7.4 用例执行结果分布（环形图）

- 纯 SVG 实现，不依赖第三方图表库；
- 分段：通过（绿）/ 失败（红）/ 阻塞（橙）/ 跳过（灰）；
- 中心显示用例总数；
- 右侧图例：色块 + 状态名 + 数量 + 百分比；
- 右上角切换：**本阶段 / 子任务全量**。

#### 2.7.5 缺陷分布（多维度条形图）

一个面板内切换 **4 个维度**：

| 维度 | 分组 |
|---|---|
| 严重度 | 致命 / 严重 / 主要 / 次要 / 轻微 |
| 优先级 | P0 / P1 / P2 / P3 |
| 类型 | 功能 / UI / 性能 / 安全 / 兼容性 / 其他 |
| 模块 | 支付下单 / 签约解约 / 退款流程 / 渠道路由 / 风控拦截 / 对账 … |

- 横向条形图，按数量降序；
- 每条：分组名（90px）/ 进度条 / 数值；
- 色值随维度：严重度红橙过渡；类型中 UI 紫、性能橙、安全红、功能蓝。

#### 2.7.6 各测试阶段进度与通过率

- 每个阶段一行，包含：
  - 阶段名 + 状态徽标（已完成 / 进行中 / 未开始）+ 时间范围；
  - 分段进度条：通过 / 失败 / 阻塞 / 跳过 四段；
  - 元信息：`通过 X · 失败 Y · 阻塞 Z · 跳过 W`，右侧"通过率 N%"；
- 右上角"前往执行管理 →" 跳 `proto-execution.html`。

#### 2.7.7 团队负荷（处理缺陷数 TOP）

- 列出处理缺陷数排名前 5 的成员 + "其他"合并项；
- 每行：头像 + 姓名 + 水平柱（按占比）+ 数量；
- 用于评估修复压力分布，识别人员瓶颈。

#### 2.7.8 风险与遗留问题

- 每项三级色带：高 `lv-high`（红）/ 中 `lv-mid`（橙）/ 低 `lv-low`（蓝）；
- 字段：图标 + 标题 + 描述（状态/处理人/附注）+ 元信息（遗留/建议/缺陷号）+ "查看 ›"；
- 点击"查看 ›" → 跳缺陷详情或文档页。

#### 2.7.9 近 7 日缺陷新增 / 关闭趋势

- SVG 双线图：新增（红）/ 关闭（绿）；
- X 轴为日期（7 天），Y 轴自动计算 max；
- 底部图例 + 最后更新时间。

#### 2.7.10 测试结论区

**3 宫格摘要**：

| 格 | 口径 |
|---|---|
| 用例覆盖率 | 已设计案例数 / 需求点数 × 100% |
| P0/P1 缺陷修复率 | P0+P1 已关闭 / P0+P1 总数 × 100% |
| 回归通过率 | 回归用例通过 / 回归用例总数 × 100% |

**结论正文**（富文本）：
- 三段结构：`整体评估` / `遗留风险` / `建议`；
- 每段带蓝色前置标签；
- 支持加粗关键指标。

**签署区**：

| 角色 | 签署要求 | 状态 |
|---|---|---|
| 测试负责人 | 必签 | 已签署 / 待签署 |
| 开发负责人 | 必签 | 同上 |
| 产品负责人 | 必签 | 同上 |

- 操作：`催签`（向待签人发通知）/ `归档`（全部签署后可归档至知识库）。
- 归档后报告状态变为"已归档"，不可再编辑，但可查看/导出。

#### 2.7.11 历史报告模态

- 弹窗 720px，列表字段：报告编号 / 名称 / 类型 / 状态（已归档 / 评审中 / 草稿）/ 负责人 / 生成时间 / 查看。
- 点击"查看"：关闭弹窗并加载该报告（替换主区数据）。

#### 2.7.12 数据来源与刷新

- 所有指标实时计算自执行管理、缺陷管理、评审管理的数据，不额外存储；
- 点击"重新生成"或切换报告类型 → 重新拉取并计算；
- 为保证评审证据不变，**归档**时快照一份 JSON 数据存档。

> 对应原型：`proto-report.html`

### 2.8 评审管理

覆盖测试计划、测试设计、测试总结三类核心评审。主视图为"表格"，支持按子任务范围筛选与多条件搜索。

#### 2.8.1 顶栏范围筛选

- 测试子任务：支持"全部子任务"，与其他页面共享选中值（当选"全部子任务"时不回写全局，避免覆盖其他页面）。
- 主区范围：评审范围下拉（全部 / 我发起的 / 我参与的 / 待我评审）。

#### 2.8.2 评审概览（6 张卡片）

| 卡片 | 说明 |
|---|---|
| 评审总数 | 当前范围全部评审 |
| 待评审 | 已发起未开始 |
| 评审中 | 进行中（脉冲指示） |
| 已通过 | 通过数量 + 通过率 %（分母=已通过 + 未通过） |
| 未通过 | 需重新评审 |
| 已取消 | 废弃 / 作废 |

#### 2.8.3 评审列表

| 区域 | 内容 |
|---|---|
| 工具栏 | 搜索（编号 / 标题 / 发起人 / 参与人）、评审类型、评审方式、状态、发起人、重置 |
| 表头 | 评审编号、评审标题（附评语副文案）、评审类型、评审方式、关联子任务、发起人、参与人（头像组）、评审时间、状态、评审结果（进度条：通过数 / 总数）、操作（查看 / 结论 / 导出） |

**参与人头像组**：最多显示 5 个头像，第 6+ 用"+N"圆形数字代替；悬浮显示完整成员列表。

#### 2.8.4 评审字典

| 维度 | 取值 |
|---|---|
| 评审类型 | 测试计划 / 测试设计 / 测试总结 |
| 评审方式 | 邮件评审 / 会议评审 |
| 评审状态 | 待评审 / 评审中 / 已通过 / 未通过 / 已取消 |

#### 2.8.5 评审-待办联动

- 作为参与人且评审处于待评审 / 评审中 → 自动出现在工作台"我的待办"的"评审"分类。
- 点击工作台待办项 → 跳转评审管理详情页，并携带评审编号定位。
- 评审结论（通过 / 未通过）会回写关联的任务 / 子任务状态，驱动任务进入下一流程：
  - 测试计划评审通过 → 任务状态从"草稿"→"设计中"；
  - 测试设计评审通过 → 相关案例批量变"已通过"，任务从"设计中"→"执行中"；
  - 测试总结评审通过 → 任务从"评审中"→"已完成"。

#### 2.8.6 发起评审表单

**必填**：标题、评审类型、评审方式、关联子任务、参与人（≥1）、评审时间、评审材料链接。

**可选**：@特别提醒、截止时间、附件。

**校验**：会议评审模式下必填"会议室/会议链接"；邮件评审模式下自动生成评审邮件草稿。

> 对应原型：`proto-review.html`

## 3. 非功能需求

### 3.1 性能

| 指标 | 目标值 |
|---|---|
| 首屏渲染（工作台） | ≤ 1.5s（P95） |
| 任务切换 → 页面刷新 | ≤ 500ms |
| 表格分页切换 | ≤ 300ms |
| 报告重新生成 | ≤ 2s |
| 导出 PDF（单份报告） | ≤ 5s |

### 3.2 兼容性

- 浏览器：Chrome 100+ / Edge 100+ / Safari 15+；**不兼容** IE。
- 分辨率：最低 1366×768；主力适配 1440×900 / 1920×1080。
- 响应式：页面 ≤ 1200px 时 KPI / 任务卡自动降列。

### 3.3 可访问性

- 所有可点击元素有 hover / focus / active 三态样式；
- 颜色不作为唯一信息载体（徽章同时带文字）；
- 关键操作 Toast 提示 1.8s；危险操作（删除 / 归档）二次确认。

### 3.4 安全与合规

- 任务 / 子任务 / 报告等敏感数据按角色与任务参与关系鉴权；非参与人仅列表可见，详情需申请权限；
- 所有变更记录审计日志（操作人 / 时间 / IP / 变更字段）；
- 报告归档后数据做快照不可篡改；导出 PDF 加水印（报告编号 + 查阅人）。
