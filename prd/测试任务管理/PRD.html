1. 需求概述

1.1 需求背景

随着业务版本迭代加速，测试团队面临多任务并行、跨角色协同、信息分散等问题：

  • 任务散落：案例、执行记录、缺陷、评审分散在 Excel、禅道、飞书文档等多个系统中，无法形成闭环视图。
  • 切换成本高：测试工程师通常同时参与 3~5 个并行任务，系统缺少统一的"任务上下文"入口，每次切换都需要多次跳转。
  • 进度不透明：管理者难以快速掌握各任务的设计 / 执行 / 评审进度，无法及时识别风险。
  • 协作低效：评审、审批、缺陷指派等流程依赖线下沟通，缺少统一待办入口。
  • 报告手工化：测试报告多由测试负责人手动撰写 Word/PPT，指标口径不统一，归档与追溯困难。

本次需求构建统一的测试任务管理平台（TMS），将测试生命周期内的所有工作聚合到"一个任务 + 一个上下文"下，提升测试团队的协同效率与过程透明度。

1.2 目标与价值

核心思路：以"测试任务"为核心对象，以"测试子任务 / 测试阶段 / 测试轮次"为全局测试范围上下文，一站式串联设计、执行、缺陷、报告、评审五大环节。

一个上下文，全页贯通
左上任务切换器 + 顶部"测试子任务 / 阶段 / 轮次"下拉；切换一次，设计 / 执行 / 缺陷 / 报告 / 评审五个菜单同步生效。
一个工作台，三秒进入状态
首页卡片化展示"我的任务 + 我的待办 + 团队动态 + 公告"，统计卡与下方面板双向联动。
全链路闭环
设计 → 执行 → 缺陷 → 报告 → 评审 模块数据打通；执行失败一键提 Bug，报告一键发起评审，评审结果回写任务状态。
过程可度量
任务进度、案例覆盖、缺陷分布、通过率、评审通过率等关键指标实时可视。

1.3 功能范围与菜单结构

2. 需求内容

2.1 全局框架与上下文

平台的所有业务页面共用统一的顶栏与左侧菜单。顶栏承担两类核心上下文入口：当前测试任务 与 当前测试范围（子任务 / 阶段 / 轮次）。

2.1.1 顶栏区域结构

区域尺寸说明
左侧：任务切换器宽 200px · 高 52px与左侧菜单同宽；显示当前任务名称（不再显示 LOGO 与产品名）；悬浮在右侧浮出 tooltip 完整展示任务名。点击展开下拉：搜索框 + 最近访问（TOP5）+ 我参与的 + 新建任务（置底）。
中部：页面标题—显示当前菜单名，左侧细竖分隔线，不展示面包屑。
右侧：测试范围下拉自适应设计 / 缺陷 显示"测试子任务 + 测试阶段"；执行 额外显示"测试轮次"；报告 显示"测试子任务 + 测试阶段（仅阶段报告模式启用）"；评审 仅显示"测试子任务"。字段前红色星标表示必选。
右上角—不显示消息、搜索、帮助、用户等图标。

2.1.2 左侧菜单

  • 宽 200px，深色背景（#1e2736），7 个菜单项：工作台 / 测试任务 / 设计管理 / 执行管理 / 缺陷管理 / 测试报告 / 评审管理。
  • 菜单项不显示待办数角标，也不显示分组标题，保持极简。
  • 菜单激活态：背景加深 + 左侧 3px 蓝色竖条（#0052d9）。
  • 图标采用 Unicode 几何符号（◈ ◎ ◇ ▷ ◆ ◫ ◐），保证跨平台一致。

2.1.3 全局任务切换（TMSGlobal）

  • 全局对外 API：TMSGlobal.mount / getCurrentId / setCurrent / upsertTask / onChange。
  • 任务池以 localStorage 保存，支持跨 Tab 同步；切换任务后所有已挂载页面通过 onChange 统一刷新。
  • 切换成功后在页面顶部弹出 Toast："已切换到 XXX"（1.8s 自动消失）。
  • 工作台任务卡片点击可触发 setCurrent；任务列表"任务编号"列点击也可触发切换，当前任务行左侧有蓝色竖条 + "● 当前"徽标。
  • 下拉面板分组：最近访问（TOP5）/ 我参与的（全部）/ 搜索结果 / ＋ 新建任务（置底）。

2.1.4 全局测试范围切换（TMSScope）

  • 范围维度：测试子任务 · 测试阶段（ST 阶段 / UAT 阶段 / 合并测试阶段）· 测试轮次。
  • 通过 localStorage 以可见名称持久化，跨页 / 跨 Tab 共享。
  • 各页面下拉通过 TMSScope.pickMatch 按名称匹配（忽略大小写 / 空格），匹配不到时回落到该页默认值并回写全局。
  • 切换主任务时：子任务 / 阶段 / 轮次自动清空，由各页按其任务的默认子任务重建下拉。
  • 评审管理选择"全部子任务"时不回写全局，避免覆盖其他页面的精确选择。
设计要点：任务切换器是"主上下文中枢"，测试子任务 / 阶段 / 轮次是"细粒度上下文"。两者分别解决"换任务"与"换测试范围"的问题，在任意菜单页都保持联动。工作台除外（展示跨任务的个人聚合视图）。

2.2 工作台

工作台是登录后的默认落地页，定位为"个人聚合视图"，跨任务展示当前用户关联的所有信息。顶部仅展示副标题"欢迎回来，XXX · 今天是 YYYY 年 M 月 D 日 周 X"。

2.2.1 页面结构

工作台 ├─ 副标题（欢迎语 + 日期） ├─ 数据总览（4 张统计卡，可点击联动） ├─ 左右主栏（grid: 1fr 380px） │ ├─ 左列 │ │ ├─ 我的测试任务（2 行 × 3 列 + 更多） │ │ ├─ 快捷入口（6 项） │ │ └─ 团队动态（时间线） │ └─ 右列 │ ├─ 我的待办（全部 / 逾期 / 今日 Tab） │ └─ 公告 & 消息

2.2.2 数据总览（4 张可点击统计卡）

卡片指标口径点击联动配色
进行中任务当前用户参与、状态 ∈ {设计中 / 执行中 / 评审中} 的任务数滚动并高亮"我的测试任务"面板，自动切到"执行中" Tab蓝
待办事项"我的待办"全部未完成项总数滚动并高亮"我的待办"面板，切到"全部" Tab橙
待处理缺陷指派给我 & 状态 ∈ {待处理 / 重开}跳转缺陷管理，预置"处理人=我 + 状态=待处理/重开"红
本月已完成本月完成执行的案例数 + 关闭的缺陷数跳转团队动态，按"我的 + 本月"筛选绿
  • 主数值 26px · 600 字重；悬浮变 #0052d9。
  • 副文案格式："较上周 ↑12%" / "其中致命+严重 5"。
  • 悬浮：左侧浮出 3px 竖条（对应卡片色系），边框变蓝，阴影 0 2px 8px rgba(0,82,217,.08)。
  • 点击：下方对应面板闪烁一次高亮边框（panelFlash 1.2s 动画）。

2.2.3 我的测试任务（2 行 × 3 列 + 更多）

  • 布局：4 列固定，默认显示 2 行最多 8 张卡；超过 8 条时显示「更多 (剩余 N)」按钮，点击一次展开下一批 8 条（4×2），逐批懒加载，无上限。
  • Tab 筛选：全部 / 设计中 / 执行中 / 评审中 / 已完成；每 Tab 带数量角标。
  • 空态："暂无任务，点击左上角切换或 + 新建"。
字段展示样式说明
任务名称13.5px · 600 字重，单行省略 + Tooltip点击卡片：切换为当前任务（TMSGlobal.setCurrent），所有菜单页上下文同步；当前任务卡左侧 3px 蓝条 + 右上角"● 当前任务"徽标。
子任务总数12px 灰色副文案"共 N 个子任务"，取当前任务的子任务配置计数。
卡片不展示进度条、ST/UAT 状态徽标等详细信息，保持极简；详细信息在"测试任务"菜单展开。

2.2.5 我的待办（分类 Tab + 默认 10 条 + 更多）

Tab：全部 / 逾期 / 今日；每 Tab 带计数。

类型图标底色来源处理跳转

  • 左 3px 竖条表示优先级：红（高）/ 橙（中）/ 灰（低）。

  • 团队动态：时间线样式，含头像 + 姓名 + 动作 + 对象 + 时间；动作类型含：提交案例 / 关闭缺陷 / 完成执行 / 创建任务 / 发起评审 / 归档报告；默认 10 条。
  • 公告：每条含 tag：置顶 / 系统 / 规范；默认 5 条，置顶项固定在顶部。

  • 必填：任务编号（系统自动生成，可改）、任务名称、所属业务线、测试负责人、ST 负责人、UAT 负责人、截止日期、子任务配置（≥1）。
  • 子任务配置：子任务名称 + 涉及阶段多选 + 子任务负责人。
  • 阶段枚举（固定 3 项）：
    • ST 阶段（系统测试）
    • UAT 阶段（用户验收）
    • 合并测试阶段

2.4 任务详情

3.5.2 前端自动接入机制（tms-api.js）

tms-api.js 是所有业务页面的通用接入器，页面只需按约定暴露 window.__TMS_HOOKS__，即可获得"加载 → 脏检测 → 自动写回 → 切换任务刷新"全链路能力。

Hook key页面必填方法需 taskId
taskList测试任务getData / setData否
design设计管理getData / setData是
execution执行管理getData / setData是
defect缺陷管理getData / setData是
review评审管理getData / setData是
report测试报告getData / setData是
workbench工作台applySummary(payload) / mergeTodos(items)是（逐任务聚合）
  • 加载：DOMContentLoaded 后，按当前任务拉取资源，调 setData 覆盖；后端空数据时保留本地种子。
  • 脏检测：每 800ms 比较 getData() 的 JSON 快照与 baseline，不同则 300ms 防抖后 PUT 整表。
  • 任务切换：先 flush 当前任务未落盘数据 → reload 新任务；跨 Tab 同步由 TMSGlobal 承担。
  • 离开页面：beforeunload 时 navigator.sendBeacon 兜底 PUT，避免丢数据。
  • 合并策略：任务列表 taskList 特殊处理——后端字段优先，本地特有展示字段（subtasks 摘要、tags 等）按 id 合并保留，避免"展开行子任务空"。
